# CodeGraph 使用提示词

## 不使用 CodeGraph

```text
这个任务不用 CodeGraph。

原因：
- 只是普通讨论 / 文档 / 小脚本 / 明确的小修改。
- 直接读取相关文件即可。

要求：
不要初始化 CodeGraph。
不要安装新依赖。
不要修改环境配置。
```

## 新项目接手

```text
请先判断这个项目是否适合使用 CodeGraph。

如果已有 .codegraph 或 CodeGraph 可用：
先用 CodeGraph 做项目 onboarding，输出：
1. 项目入口
2. 核心模块
3. 主要调用链
4. 测试和构建方式
5. 高风险区域

如果没有 CodeGraph：
先说明是否值得初始化、会产生什么文件、有什么风险，不要直接安装或初始化。

暂时不要修改代码。
```

## 复杂 Bug 分析

```text
请用 CodeGraph 辅助定位这个 bug。

流程：
1. 先查相关入口、调用方和被调用方。
2. 再读取关键源码确认真实逻辑。
3. 输出根因判断、影响范围和修复方案。
4. 等我确认后再修改代码。

不要只根据 CodeGraph 结果下结论，必须回到源码验证。
```

## 核心功能修改

```text
这是核心流程修改，请先用 CodeGraph 做影响分析。

输出：
1. 相关函数、类、模块
2. 调用方和被调用方
3. 可能受影响的功能
4. 需要阅读的关键源码
5. 建议修改方案
6. 建议测试范围

确认方案前不要改代码。
```

## 代码审查

```text
请用 CodeGraph 做结构级代码审查。

重点看：
1. 调用关系是否合理
2. 核心模块是否存在高风险耦合
3. 公共函数修改是否影响多个调用方
4. 异常和边界情况是否被上层处理
5. 是否缺少关键测试

输出问题时按严重程度排序，并给出文件和原因。
```
